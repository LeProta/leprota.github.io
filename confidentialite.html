L’essentiel. Le composant d’archivage dépose des PDF validés dans le Drive autorisé, conserve les éditions datées et met à jour une copie courante. Les documents ne sont pas publiés sur ce site.

1. Périmètre et responsable

Cette politique décrit le composant personnel « Journal Financier - archivage » du projet Le Journal Financier, géré par le propriétaire du compte GitHub LeProta. Elle explique son accès OAuth à Google Drive et le traitement des éditions produites par le projet.

L’application est utilisée pour les besoins de son propriétaire. Pour une question relative à la connexion Google ou aux documents, le contact d’assistance est celui indiqué sur l’écran de consentement Google de l’application. Le profil GitHub du responsable est également lié depuis ce site.

2. Données Google accessibles

Le client OAuth d’archivage demande la portée https://www.googleapis.com/auth/drive.file. Elle permet de consulter et de gérer les fichiers créés par l’application ou explicitement autorisés pour elle, plutôt que l’ensemble des fichiers du compte.

Les opérations d’archivage utilisent :

  • les PDF produits et validés par le projet, envoyés au dossier Drive choisi ;
  • les identifiants et liens des fichiers et du dossier, leurs noms, types, tailles, parents, propriétés de date et empreintes de vérification ;
  • les informations d’autorisation OAuth, notamment les jetons d’accès et de renouvellement, nécessaires pour authentifier les appels Google.

L’accès éventuel aux cours utilise une connexion de lecture séparée, configurée par le propriétaire. L’autorisation d’archivage ne remplace pas cette connexion et ne transforme pas les supports de cours en documents publics.

3. À quoi servent ces données ?

Elles servent à archiver les éditions datées, maintenir une copie courante à lien stable, contrôler l’intégrité des fichiers déposés, éviter les doublons et enregistrer le résultat des livraisons. Le logiciel ne supprime pas automatiquement les éditions datées.

Le composant OAuth d’archivage intervient après la rédaction et les contrôles du PDF. Il n’envoie pas les fichiers ou métadonnées qu’il récupère de Drive à un modèle d’intelligence artificielle et ne les utilise pas pour développer, améliorer ou entraîner des modèles d’IA généraux.

Les fonctions distinctes de rédaction et de relecture du projet peuvent utiliser le fournisseur d’IA expressément configuré par le propriétaire. Lorsqu’une rubrique pédagogique issue d’une connexion séparée est activée, les extraits de cours présents dans un PDF peuvent faire partie des pages examinées par le contrôle visuel configuré. Les autorisations et conditions de ces fonctions doivent être examinées dans le parcours privé correspondant.

Le projet ne vend pas les données Google et ne les utilise pas à des fins publicitaires.

4. Où les données sont-elles traitées ?

  • Google Drive conserve les fichiers déposés dans le compte autorisé et applique leurs permissions d’accès.
  • GitHub Actions, lorsqu’il est utilisé, exécute les tâches de préparation ou de livraison. Le dépôt du journal, son historique et ses diagnostics sont configurés comme privés.
  • Pushcut, si les notifications sont activées, reçoit le déclenchement de la notification prédéfinie. Dans le mode gratuit retenu, aucun PDF ni contenu dynamique n’est joint à l’appel. Le lien Drive fixe est configuré une fois dans l’app par le propriétaire.
  • Le poste local du propriétaire peut conserver les configurations, copies de travail, journaux et sauvegardes nécessaires au projet.

Les prestataires traitent également les données techniques nécessaires à leurs services selon leurs propres conditions. L’archivage ne crée pas de partage public du dossier Drive ou des PDF.

5. Conservation

Les PDF datés et l’historique du journal sont conservés jusqu’à leur suppression par le propriétaire. La copie courante est mise à jour avec l’édition validée retenue ; les archives datées restent distinctes.

Les reçus de livraison sont conservés dans le stockage privé du projet. Les artefacts de diagnostic des workflows de livraison sont configurés avec une durée de conservation de sept jours. Les copies de travail et sauvegardes présentes sur le poste du propriétaire restent sous son contrôle.

Les identifiants de connexion restent dans les fichiers privés ou les secrets GitHub jusqu’à leur remplacement, suppression, expiration ou révocation. Aucune durée de validité illimitée n’est garantie pour une autorisation Google.

6. Protection des données

Les échanges avec les API Google passent par HTTPS. Les fichiers de connexion locaux utilisés pour l’archivage ont des permissions d’accès restreintes ; les secrets des workflows sont enregistrés comme secrets GitHub. Ils ne sont pas intégrés aux PDF, au site public ou à l’export du code du journal.

Le script vérifie les métadonnées et les empreintes des fichiers distants avant de notifier leur disponibilité. Un résultat d’envoi incertain demande une vérification avant reprise afin de limiter les notifications répétées.

7. Vos autorisations et vos documents

Le propriétaire peut retirer l’accès de l’application depuis les connexions tierces de son compte Google, désactiver la livraison dans les paramètres privés du projet et supprimer les identifiants enregistrés.

La révocation empêche les accès futurs qui dépendent de cette autorisation ; elle ne supprime pas automatiquement les fichiers déjà créés. Pour supprimer les données conservées, le propriétaire doit aussi gérer le dossier Drive, les archives et sauvegardes locales, les artefacts et l’historique privé GitHub concernés. Les mécanismes de corbeille, de sauvegarde et de conservation propres aux prestataires continuent de s’appliquer.

Une nouvelle utilisation des données ou une extension des permissions doit être accompagnée d’une information appropriée et d’une mise à jour de l’autorisation concernée.

Lecture privée dans l’application

Le lecteur peut afficher les éditions sous forme d’articles séparés, avec leur source, leur illustration et les exercices pédagogiques validés. Ces données sont conservées dans un dossier privé du Drive du propriétaire. Le site public contient le code de l’interface et des illustrations génériques, mais aucun article ou extrait de cours privé.

Une connexion Google Web distincte est nécessaire pour consulter ces fichiers. Google Identity Services fournit un jeton d’accès temporaire, conservé uniquement en mémoire pour la session. Le lecteur utilise la portée drive.file, limitée aux fichiers utilisés avec l’application ; cette portée permet leur gestion côté Google, mais le lecteur n’effectue que des requêtes de consultation. Le client d’archivage continue à assurer le dépôt séparément.

Le lecteur récupère le catalogue des éditions, les articles, les sources, les médias et la fiche pédagogique de l’édition demandée. Il vérifie les formats et les empreintes avant affichage. Les fichiers sont chargés en mémoire ; cette version ne conserve pas de copie privée hors connexion. À la déconnexion ou à l’expiration de la session, les références d’accès sont retirées et les contenus ne sont plus présentés dans l’interface.

Les préférences d’apparence et de taille de lecture restent enregistrées sur l’appareil. Les favoris conservent uniquement les identifiants des articles, sous un espace de noms dérivé d’un identifiant du compte Drive. Aucun email ni contenu d’article n’est enregistré dans ces préférences. Google peut traiter les informations techniques liées au chargement de sa bibliothèque de connexion et à l’autorisation selon ses propres conditions.

Lorsqu’un hébergement avec session durable est activé, le navigateur conserve un cookie de session sécurisé et non accessible au code JavaScript. Les autorisations Google sont conservées chiffrées côté serveur, dans un stockage privé, et renouvelées lorsque cela est possible. L’adresse du compte Google sert à limiter l’accès au propriétaire configuré. La session est renouvelée pendant l’utilisation et expire après trente jours d’inactivité ; une révocation Google peut imposer une nouvelle connexion plus tôt. La déconnexion supprime la session côté serveur. En cas d’échec réseau pendant cette opération, un indicateur local bloque la reprise automatique jusqu’à confirmation de la déconnexion. Ce mode nécessite un hébergement serveur ; il n’est pas activé par la simple consultation du site GitHub Pages.

Déconnecter le lecteur ne supprime pas les fichiers de Drive et ne révoque pas la connexion d’archivage utilisée par GitHub. Le propriétaire peut gérer ces autorisations depuis son compte Google et effacer les données locales du site depuis son navigateur.

Notifications web facultatives

Après installation sur l’écran d’accueil et autorisation volontaire, le navigateur crée un abonnement Web Push propre à l’appareil. Son adresse technique et ses clés de chiffrement sont copiées par le propriétaire dans un secret de son dépôt GitHub privé ; elles ne sont pas publiées sur ce site. La clé privée d’envoi reste également dans un secret privé. Le site ne possède pas de serveur d’inscription.

GitHub Actions peut envoyer un message chiffré contenant le titre, le texte, la date et le lien du PDF validé au service de notifications du navigateur (notamment Apple pour l’iPhone). Le système de l’appareil affiche ce message. Le texte peut être visible sur l’écran verrouillé selon les réglages du propriétaire. Les PDF et les cours ne sont pas joints aux notifications.

L’application conserve dans le navigateur les préférences d’affichage et, dans IndexedDB, les liens des dix dernières notifications pour permettre leur ouverture. Elle ne met pas les PDF en cache. Ces données locales peuvent être effacées avec le bouton de désactivation, ou en supprimant les données du site. La désactivation révoque l’abonnement sur l’appareil ; le propriétaire doit aussi supprimer l’ancien secret GitHub. Un nouvel abonnement devra être enregistré dans GitHub si le navigateur le renouvelle.

Les notifications ne sont pas activées par une simple visite. La copie d’un abonnement ne prouve pas la réception : un essai depuis GitHub et une vérification sur l’iPhone restent nécessaires.

8. Ce site public

Ces pages présentent l’application et sa politique de confidentialité. Elles ne proposent pas de connexion Google, ne recueillent pas de document et ne contiennent pas les éditions privées.

Le site n’ajoute aucun outil d’analyse d’audience, formulaire ou traceur publicitaire. Son hébergeur GitHub Pages peut traiter les données techniques de consultation selon la politique de confidentialité GitHub.

La présente politique sera mise à jour si les pratiques décrites changent. Le nom de l’application et la date de mise à jour permettent d’identifier la version applicable.
